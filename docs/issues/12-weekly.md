# [Refactor] 주간 식단 생성의 반복 조회 제거 및 빈 음식 목록 처리

대상: 새 이슈

### 📋 작업 내용
주간 식단 생성에서 음식 목록을 한 번 조회하고 데이터 부족 정책을 적용한다.

**우선순위:** P2 · 조회 비용 및 초기 환경 안정성
**검토 기준:** `feat/global-exception-handler` / `4c4f5ad366b4dd27338e027e1e3e9c6bf56c2814`

### 🔍 현재 상황
- 7일 × 세 끼마다 getRandomFoods가 findAll을 호출하여 같은 음식 목록을 21번 조회한다.
- 음식이 없으면 random.nextInt(0)으로 실패한다.
- 복원 추출이므로 같은 끼니에 동일 음식이 중복될 수 있다. 이것이 허용되는지 업무 규칙이 명확하지 않다.

### ✅ 할 일
- [ ] 생성 시작 시 음식 목록을 한 번 조회하고 각 끼니 선택에서 재사용한다.
- [ ] 음식 0개인 경우 명확한 오류 또는 생성 보류로 처리한다.
- [ ] 끼니 내 중복 허용 여부와 3개 미만일 때의 정책을 정해 적용한다.

### 🧪 검증 및 완료 기준
- [ ] 주간 생성 한 번에 음식 목록 조회가 한 번만 일어난다.
- [ ] 음식 0/1/2/3개 이상에서 정한 정책대로 동작한다.
- [ ] 7일 × 끼니 구성과 날짜 범위를 유지한다.
