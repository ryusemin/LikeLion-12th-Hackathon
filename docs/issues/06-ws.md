# [Fix] WebSocket CONNECT 인증 및 사용자 구독 권한 검증

대상: 새 이슈

### 📋 작업 내용
클라이언트 이메일 주장을 신뢰하지 않고 검증된 인증 정보로 WebSocket 사용자를 설정한다.

**우선순위:** P0 · 개인 알림 보호
**검토 기준:** `feat/global-exception-handler` / `4c4f5ad366b4dd27338e027e1e3e9c6bf56c2814`

### 🔍 현재 상황
- CONNECT의 userEmail 또는 핸드셰이크 쿼리로 사용자 Principal을 만든다.
- 이메일만 바꿔 다른 사용자 신원을 주장할 수 있고 메시지·구독 권한 검사도 필요하다.
- 허용 Origin에 https://nimn.store가 없어 해당 HTTPS 화면의 브라우저 연결이 거절될 수 있다.

### ✅ 할 일
- [ ] CONNECT에서 Access Token의 서명·만료·용도를 검증하고 Principal을 설정한다.
- [ ] 클라이언트가 전달한 userEmail을 인증 근거로 사용하지 않는다.
- [ ] 사용자별 구독·메시지 대상 권한을 검사한다.
- [ ] 실제 프론트 Origin에 맞게 허용 목록을 수정한다.
- [ ] 연결·재연결·해제 시 인증 및 세션 정리 흐름을 맞춘다.

### 🧪 검증 및 완료 기준
- [ ] 토큰 없음·만료·다른 사용자 사칭 CONNECT를 차단한다.
- [ ] 사용자 A의 토큰으로 사용자 B의 개인 알림을 수신할 수 없다.
- [ ] 허용 HTTPS Origin 연결 및 재연결을 확인한다.
